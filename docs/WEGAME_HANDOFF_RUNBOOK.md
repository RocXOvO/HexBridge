# WeGame 实机综合验收

本清单用于一次闭环验证交接、终局、窗口、OCR、96px 提示、战绩、更新与可选数据源。它是发布后的真实环境门禁，不能由单元测试、Windows Actions、重命名进程、fake window 或 packaged smoke 替代。

## 前置条件

- 使用 GitHub Releases 当前唯一正式版本；先在窗口左上角确认版本号。
- Windows 10/11 x64、国服 WeGame、海克斯大乱斗。记录 LCU 实际 queueId：公开配置通常为 `2400`，国服自定义房间已实机观测到 `3270`。
- 游戏使用无边框模式；设置中启用“选人浮窗”和“三卡上方推荐”。自动 OCR 开 / 关各验一次。
- 使用 v0.1.35 或之后版本，测试前打开 HexBridge“诊断”页。重点观察“选人伴随窗”“游戏内推荐条”以及伴随窗卡片下方的窗口观察状态；这些字段都是有限枚举，不含 PID、HWND、位置或标题。
- 诊断页只展示受控状态字段；不要另行发送 LCU `lockfile`、token、完整 champ-select session、PUUID、API Key、用户名或本地路径。

## v0.1.35 脱敏呈现检查点

同一局只需截取诊断页相应卡片，不需要截完整桌面：

1. 选人确认后：“选人伴随窗”应最终为“正在显示”；窗口观察应为“窗口观察正常”。若不是，保留“尚未确认客户端窗口 / 正在等待窗口状态 / 英雄联盟客户端不可见 / 正在贴合客户端”等原始中文状态。
2. 首次三卡稳定后：“游戏内推荐条”应为“正在显示”；若为“尚无当前三卡结果 / 三卡结果不完整 / 游戏不在前台，已隐藏”，不要手工改写描述。
3. 刷新卡牌后：旧条先撤下，稳定识别 3/3 后重新回到“正在显示”；记录从画面稳定到恢复显示的时间。
4. 选卡约 2 秒后：“游戏内推荐条”应变为“尚无当前三卡结果”，主窗口可继续保留最后一次三卡供回看。
5. 退出房间约 15 秒后：“选人伴随窗”为“当前阶段无需显示”，“游戏内推荐条”为“当前不在游戏阶段”。“等待页客户端背景”关闭时窗口观察应为“观察未运行”；显式开启背景时可继续观察 Lobby 窗口，但不得保留对局浮窗或三卡条。

若状态与可见窗口相冲突，同时提供同一分钟内已过滤的 `Window presentation transitioned`、`LCU match context transitioned` 与 `Manual OCR completed / failed` 行；不要发送整份原始日志。

## 必须观察的状态链

诊断页的 `LCU match context transitioned` 行应按同一英雄、同一 `matchGeneration` 连续推进。具体 phase 可能因国服客户端时序略有不同，但必须满足以下不变量。

### 1. 选人确认

- `matchStage=selecting`
- `queueId=2400` 或已验证的国服 `3270`
- `championId` 是当前英雄
- `contextDecision=confirmed`

记录英雄名称 / ID 与 `matchGeneration`。

### 2. 最后等待与 LeagueClientUx 交接

允许出现下列一种或多种状态：

- `reason=transport-unavailable` 且 `contextDecision=retained-transport-handoff`
- `reason=auxiliary-request-failed` 且 `contextDecision=retained-partial-observation`
- phase 仍为 `ChampSelect`、session/current 已 `empty` 或 `error`，且 `contextDecision=retained-outgoing-champ-select`
- `phase=None` 或地区特有未知 phase，但 `matchStage=launching`

这一阶段必须继续满足：

- `queueId` 与选人确认时相同
- `championId` 与选人确认时相同
- `matchGeneration` 不变
- 主窗口仍显示当前英雄
- 选人浮窗显示“进入游戏中 / 本局英雄已保留”
- 英雄详情与推荐不得变成另一位英雄的数据

### 3. 游戏客户端启动

进入实际游戏后，应由可靠证据升级为 `matchStage=active`：

- LCU 报告 `InProgress` / `Reconnect`；或
- `reason=game-process` 检测到对应游戏进程；或
- `reason=augment-interface` 首次可靠识别三张海克斯。

必须继续使用同一英雄和同一 `matchGeneration`。选人浮窗此时按设计隐藏，OCR / 海克斯推荐继续运行。

### 4. 终局清理

`WaitingForStats / PreEndOfGame / EndOfGame / Lobby` 等可靠终局状态应产生 `contextDecision=cleared-terminal-phase`，随后：

- `matchStage=none`
- 当前英雄、详情与海克斯 overlay 被清理
- OCR 停止

### 5. 第二局换代

同一海克斯大乱斗 queueId 的下一次选人也必须开启新 generation：

- 新英雄未确定前不得短暂回显上一局英雄
- 新英雄确认后 `matchGeneration` 必须递增
- 新英雄详情替换旧英雄详情
- 上一局迟到的详情或 OCR 结果不得覆盖第二局

### 6. LeagueClientUx 跟随

在选人期依次移动、缩放、最小化和恢复 LeagueClientUx，并在 100% / 125% / 150% DPI 中至少覆盖本机实际使用的一档：

- 伴随窗应在约一个可感知不到的短周期内跟随，不持续漂移、左右跳动或吸附到另一个 LeagueClientUx。
- 边缘间距保持一致，不覆盖客户端主要操作区；最小化时隐藏，恢复后重新贴合。
- 全程不得抢走 LeagueClientUx 焦点，也不得因为存在第二个同名窗口改绑错误进程。

### 7. OCR 刷新与 96px 提示条

在真实三卡画面完成以下连续操作，并记录每步从画面稳定到 UI 更新的体感时间：

1. 首次出现三卡，按手动快捷键识别；主窗口与 96px 条应显示同一三张卡。
2. 96px 条必须位于完整卡面上方、点击穿透、不抢焦点，且三卡顺序 / 推荐理由与当前数据源一致。
3. 刷新一张或多张卡：旧条先撤下，新画面稳定后才提交 3/3 新结果；不得长期保留旧卡或反复完整 OCR。
4. 选择卡牌并关闭三卡界面：连续可靠 absence 后提示条应撤下；主窗口可保留最后一次结果供回看。
5. Alt-Tab 再返回：提示条只临时隐藏并按低成本探测恢复，不应重做一次昂贵完整 OCR。

若使用 data.dtodo，展示的是该英雄专属选取率；若使用腾讯来源，必须明确写“全局选取率 / 全局胜率”，不得冒充该英雄专属统计。

### 8. 对局中途启动

完全退出 HexBridge，在游戏已经 `InProgress` 后重新启动：

- 应在有界重试内恢复当前英雄、详情、OCR 资格和本局 generation。
- 不得显示上一局或非海克斯队列的英雄；失败时显示不可用状态，不猜英雄。
- 诊断与日志不得出现 PUUID、用户名、路径或原始 gameflow / history 载荷。

### 9. 队友与对手近期状态

显式开启本地实验功能后，在身份公开且完整的真实对局验证：

- 分别出现 4 位队友与 5 位对手；任一分组身份不完整只使该组不可用，全局身份歧义则两组都拒绝。
- 少于 12 个有效样本显示“样本不足”，不得生成评分或三档标签。
- 点击英雄头像可打开本局内存中的脱敏胜负、K/D/A 与时长；关闭弹窗、换局、禁用功能或退出后旧 opaque key 失效。
- UI、诊断和日志均不得出现玩家名、PUUID、gameId、原始 participant 或逐局时间戳。

### 10. 启动检查与腾讯来源

- 安装版每次完全退出再启动后都应自动做一次只读更新检查；无新版时不显示入口，不自动下载 / 安装。
- 选择腾讯来源时，即使没有 data.dtodo Key，英雄与海克斯推荐仍应可用；出装区域可独立提示需要 Key。
- 切换 dtodo / 腾讯、换英雄或进入第二局时，旧来源 / 旧日期结果立即撤销，迟到响应不得覆盖当前状态。
- 腾讯卡片显示来源与统计日期；英雄推荐顺序、全局选取率和全局胜率口径必须明确。离线 stale 必须显式标注。

### 11. 性能与背景

在相同画质和场景分别记录关闭 HexBridge、开启但自动 OCR 关闭、手动 OCR、自动 OCR 命中时的 FPS / 1% low / frametime、CPU 与 GPU：

- 手动 OCR 只产生一次有界峰值；同一卡面自动路径不得每 2 秒重复完整识别。
- cinematic / balanced / eco 三档的亮暗原画和长中文均可读；active / hidden / reduced-motion 必须进入低成本路径。
- 若启用 Lobby 背景，只在大厅 / 匹配 / 接受阶段低频显示；失焦、切页、最小化、eco、选人、进入游戏或退出时立即清除。确认没有黑帧、其他窗口内容或明显持续性能下降。

## 失败判据

出现任一情况即视为 HB-020 仍未关闭：

- 在可靠终局、明确异队列或真实下一局之前，`championId` 变为 `null`。
- 最后等待期间 `matchStage` 变为 `none`。
- 同一局交接期间 `matchGeneration` 提前改变。
- 当前英雄卡、详情、选人浮窗或 OCR 上下文消失。
- 第二局短暂显示上一局英雄，或旧详情 / OCR 覆盖新英雄。
- 进入对局后始终没有 `active`，F8 也提示“当前没有可识别的英雄 / 对局”。
- 伴随窗持续错位、抖动、错误改绑、最小化后残留或抢焦点。
- 三卡刷新后仍显示旧结果、96px 条位于卡面下方、选卡后长时间不撤下，或切屏后永久不再出现。
- 对局中途启动不能恢复当前英雄，或恢复了上一局 / 非海克斯队列英雄。
- 战绩分组人数错误、样本不足仍评分、详情 key 跨局有效，或任何身份字段泄漏到 Renderer / 日志。
- 启动未检查版本、无新版仍显示入口、自动下载 / 安装，或切换推荐来源后发生跨源混合。
- OCR / Lobby 背景造成持续明显 FPS / frametime 回退，或捕获到非绑定窗口内容。

## 状态升级规则

- 报告问题的同一台机器完成“选人确认 → 游戏客户端启动”且上下文连续，HB-020 才可从 `IN PROGRESS` 升为 `FIXED / UNVERIFIED`。
- 再完成一整局三卡 OCR / 推荐、终局正确清理和第二局正确换代，才可标为 `VERIFIED`。
- 伴随窗、96px、战绩、启动检查、数据源、视觉与性能按各自 HB 独立升级状态；完成其中一项不得外推其他项。
- 任何自动化测试或其他机器的成功都不能替代上述两项实机证据。
